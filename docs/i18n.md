# Documentation languages

The entry documents support Korean (`ko`), English (`en`), and Japanese (`ja`). The default README remains Korean to preserve existing repository links.

| Document | Korean | English | Japanese |
|---|---|---|---|
| README | [README.md](../README.md) | [README.en.md](../README.en.md) | [README.ja.md](../README.ja.md) |
| Getting started | [getting-started.md](getting-started.md) | [getting-started.en.md](getting-started.en.md) | [getting-started.ja.md](getting-started.ja.md) |

## Maintaining translations

- Update all three README versions together when changing features, setup, logging behavior, supported tools, or privacy requirements. Update the corresponding getting-started guides when onboarding changes.
- Preserve the same meaning and requirements across languages; examples and phrasing may be localized. State incomplete translation coverage explicitly rather than labeling untranslated content as localized.
- Keep a language switcher at the top of each translated document. Link to the matching-language getting-started guide and README. Identify specialist guides that remain in Korean or English.
- Keep paths, commands, source tags, product names, and `[SETUP_REQUIRED]` unchanged. Localize example prompts so readers can copy them in their preferred language.
- `AGENTS.md` is the canonical shared policy. `CLAUDE.md` stores setup, profile, and tool-specific guidance. Translated documentation describes these rules without becoming a separate policy.
- Store the user's preferred reply and logging language in their workspace profile. Task-specific language requests take precedence. Do not insert the maintainer's personal profile into the public template.
- Before publishing, check relative links, heading anchors, code fences, language navigation, and consistency of setup and permission requirements.

Specialist guides, skills, and templates are not fully translated. No machine-translation service or automatic language detection is installed by this documentation structure.
